# v2026.11.23

## Overlay Scaling

List overlays no longer grow and shrink with their window. Each one has its own **Scale** slider in its settings, and resizing the window only changes how much fits inside it. This applies to the metric overlays, Timers, Alerts, Challenges, Effects, Cooldowns, DoT Tracker, Notes, Ability Queue, and Ability Cast List. Other overlays scaling is unchanged.

An effort has been made to ensure existing layouts keep their size: each overlay's scale is set from its saved window size, in every profile. What will look different is the empty space around the content, which is now much smaller and may require the overlays to be adjusted. I apologize for this, it should be a one-time change and remain consistent going forward.

- The padding around the edge of these overlays is now a thin fixed margin. It used to grow with the overlay, so large overlays had large empty borders.
- Overlays can sit flush against the edge of the screen, since the content now reaches the edge of its window
- Row spacing no longer grows with scale. Bar spacing on metric and Challenges overlays is now set in pixels, converted from the old percentage
- Element size is independent of window size: pick how big the rows are, then how much room to give them
- Rows, icons and text stay the same size regardless of the number of entries. Metrics bars can be set to remain consistently sized across group sizes. Size the window for the largest group once
- An overlay showing only a few rows can be a small window with normal-sized text
- A metric overlay whose content does not fit its window now shrinks its header, bars and footer together, where only the bars were squeezed before
- Timers, Effects, and Cooldown overlays can now be sized to fit an exact number of elements.

## Overlay Settings

- Scale has its own card at the top of each overlay's options
- Override Global Settings moved to the bottom of each overlay's options
- The Overlays / Profiles / Global tabs and the overlay picker stay in view while scrolling

## Training Dummy Parses

- A dummy parse now counts as a kill only when the dummy dies. Parses that were abandoned or reset are no longer shown as kills
- Dummy parses have their own Overview in Analysis: DPS, crit rate, crit damage share, APM and time to kill with Parsely percentiles, the damage chart, and a breakdown of the time between global cooldowns
- The global cooldown breakdown shows every press on a timeline with slow ones in red, a list of presses that can be opened in the combat log, the time to next press per ability, and the distribution with median and mean
- New Dummy Parses page under History, listing dummy kills only, with filters for character, discipline, dummy HP and patch
- The page shows a DPS trend with one line per discipline (mirrors combined), a per-discipline summary, and a Parsely percentile on each kill's DPS
- Individual parses can be hidden from the numbers, and listed again with Show hidden
- Dummy parses no longer appear in Boss Statistics
- Existing history is re-scanned once to pick up the new data

## History

- Boss Statistics has a collapsible Disciplines card under the charts, with your numbers per discipline on the selected boss. Clicking a discipline filters to it
- Areas in the Analysis encounter list link to their Raid Summary

## Analysis

- Parsely percentiles can be hidden with a toggle in the encounter sidebar
- The encounter list tints alternate bosses, so a run of pulls on one boss reads as a block
- The Raid Summary link and the column chooser now look like buttons

## Bugfix

- Dread Master Bestia kills are no longer lost when she is pulled while the raid is still in combat with adds from the previous wipe
- Story mode Gate Commander Draxus pulls are no longer lost or merged with the trash before them when the raid stays in combat with the shield guards
- Timers and effects no longer need two saves to clear the unsaved prompt
- Editor actions moved to the drawer header
- An ability table with nothing recorded in the selected range keeps its column widths
- Empty totals show 0 instead of -0
- Fixed rare issue caused by log lines being written with timestamps prior to file generation timestamp
